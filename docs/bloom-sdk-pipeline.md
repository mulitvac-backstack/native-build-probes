# Tested native Bloom dependency pipeline

The owner requires Bloom's native SDK to build and pass its required database semantics before Headspace consumes it. Compiler fixtures, a fresh untested rebuild in the application job, or an omitted platform cannot satisfy that dependency. Source remains private; Gitea is canonical. This lane is a Headspace-compatible embedded SDK profile, not qualification of all Bloom products or every engine API.

`bloom-sdk.yml` runs six fixed standard native labels, maximum three concurrently. Inputs are an immutable public SDK recipe revision and an explicit SDK SemVer. Its source-pinned manifest identifies the private source commit/subdirectory and the exact encrypted-input archive SHA256. The separately authorized source-secret chunks are used only in the producer. Native C compilation, required database semantic CTest and native executable header checks must pass before the producer emits an SDK. All failures remain visible. Raw compiler logs never leave ephemeral private storage; only allowlisted file coordinates and error codes may be reported.

SDK deliverables are `bloom-sdk-VERSION-TARGET.aesgcm`, `bloom-sdk-VERSION-TARGET.manifest.json`, and `bloom-build-TARGET.json`. The envelope uses AES256-GCM from pinned `cryptography==46.0.3`, with a fresh 96-bit nonce and exact canonical manifest bytes as authenticated additional data. The secret is an owner-managed random 256-bit repository key, never forwarded to compilers or printed. The nonce is prepended to ciphertext/tag; the owner keeps a private durable key copy. This cryptography pin supplies binary wheels for all six runner architectures, including Windows ARM64; no dependency is built from source in the secret-bearing step.

The encrypted archive contains only the native static Bloom library, its API header and required Rust binding, capabilities, license notices and inner manifest. Engine C, build directories, tests/database files and raw logs are forbidden even inside ciphertext. macOS includes the exact tested static Crypto archive; Linux declares native dynamic OpenSSL3, and Windows uses system BCrypt. Every member has a bounded size and SHA256. ABI, source/version, producer revision/run and native test outcomes are verified; links, path escapes, duplicates, extra members, mismatched hashes and authentication failures are rejected before files are written.

GitHub retains encrypted artifacts for90days as execution receipts, not as the durable dependency authority. The owner validates all six outputs, decrypts/checks them locally, and archives only ciphertext/public metadata to the canonical Gitea dependency release `bloom-sdk-vVERSION`. A source-owned `docs/release/bloom-sdk-lock.json` pins all six target artifact names and ciphertext/manifest digests plus producer repository/workflow/run/worker SHA/recipe revision. Published dependency versions are immutable.

The Headspace release worker requires this complete source lock. It downloads fixed canonical public Gitea URLs, verifies both digests, authenticates/decrypts and checks exact source/version/native ABI/tests, then links the relocated tested SDK. It never reextracts the engine V1 source input or rebuilds the engine. No Gitea credentials are sent to Actions. An absent, expired/unavailable, mismatched or failed SDK blocks its consumer visibly. The key is used only in decryption and removed from compiler environments. Headspace's real Rust product tests and package qualification remain subsequent independent checks.

Offline evidence: real authenticated round trips across six target schemas, ciphertext/key/AAD tamper rejection, engine-source/ABI/static-Crypto omissions, authenticated archive path/link injection rejection, complete-lock checks and actual consumer relocation with no engine-source fallback. These fixtures contain no private SDK data and do not establish hosted SDK qualification. Only the actual six native producer results can create the release lock.
