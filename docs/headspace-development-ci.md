## Trusted native package lane — 2026-10-18

The separately authorized `headspace-release.yml` leaves the original generic/public compiler lane unchanged. It fetches one exact public Headspace revision from canonical Gitea and builds on the same six native standard labels. The owner-authorized private SDK archive is supplied only through encrypted repository secrets `BLOOM_SDK_01`…`BLOOM_SDK_24`, one bounded chunk per step; public repository variables specify chunk count and compressed archive SHA256. No Gitea credentials or private engine source are committed, cached, logged or uploaded. Each job verifies the digest and rejects archive links, escapes, duplicate entries and size/file-count overruns before extracting under the disposable checkout `.private/bloomdb`.

The product-owned `scripts/ci/build_bloom.py` compiles the SDK natively. Its environment JSON allows only `BLOOM_LIB_DIR`, `BLOOM_STATIC`, `BLOOM_STATIC_LIBS`, `BLOOM_EXTRA_LIB_DIRS`. The adapter then executes fixed Rust1.98.1 tests for core, AI, MCP and GPUI (excluding the retained legacy egui reference), and the actual release GPUI/MCP builds, followed by every native source-owned package format. Raw compiler output remains in bounded ephemeral temporary files; public failures contain phase/classification only. Artifact creation remains separate from install/runtime/signing qualification.

Distribution outputs are Linux DEB/RPM; macOS appZIP/DMG/PKG plus Homebrew cask; Windows MSI plus WinGet manifests. `inventory-TARGET.json` binds every file to source revision, target, version, format, byte size and SHA256. Packages remain in a private candidate directory until every required format/checksum matches; only validated compiled formats and bounded public receipts cross into the upload directory. Pinned official upload-artifact retains only this explicit allowlist for three days. The adapter never uploads the source checkout, SDK, compiler logs or user files. Root release orchestration separately downloads/validates these artifacts and uploads to Gitea; generated manager URLs must use the receipt release tag.

Development versions are `0.1.RUN_NUMBER`, preserving MSI-compatible monotonic build identity. macOS app seals are ad-hoc only; no Developer ID/notarization, Windows signing or package-registry submission is claimed. Real native installation, launch/core flow, upgrade and removal qualification remains separately reported. Unit tests cover private-input archive boundaries, checksum/format receipts and the complete source adapter. A locally constructed ARM64 DEB using controlled tiny C executables validates the DEB tooling only, not product release success. Six hosted Headspace jobs and the private portable SDK are still required before any product package can be claimed.

Each product revision additionally pins the private archive SHA256 in `docs/release/bloom-sdk-input.json`; the worker rejects mutable repository-variable changes that do not match this immutable source manifest. macOS explicitly provisions static OpenSSL3; Linux uses native libssl-dev, and the Windows SDK uses BCrypt rather than OpenSSL. Compiled distributions include the separate owner-permitted BloomDB binary notice, cJSON/OpenSSL and app/font/icon notices. An app MIT declaration never grants a private-engine source license.

After artifact audit, each native installer also runs verifier install mode. Its nonzero/block result is retained in `native_qualification` and its bounded report; it does not delete valid development packages or claim final release qualification. Missing verifier is explicitly blocked. A native GUI session, real previous-version upgrade and Fedora RPM environment may still be unavailable; these remain reportable blockers. macOS Crypto is static, Linux Crypto uses its declared distribution runtime library, Windows uses system BCrypt.
